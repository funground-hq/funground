# Design note: fonts, styles, tracking, features, variations and mixed text

**Status:** decided (D-022, 26 Sept 2026; D-042 and D-044 by Claude under D-034, 1 Oct 2026). Built in
Sprint 6 (S-054, S-053), Sprint 10 (S-090, S-091). Contract rows T10 to T14 in
[Semantic_Contract.md](Semantic_Contract.md). Code: `funground/typography.py`, `funground/formatted.py`,
the text methods of `funground/sketch.py`, `_text_ops` in `funground/renderers/cairo2d.py`.

This note adds to [Text_Subsystem_Note.md](Text_Subsystem_Note.md). Read that for the base route:
text is shaped by uharfbuzz, outlined by fontTools and drawn as paths. It is not repeated here.

## The problem

The base route had one font and one setting, the size. Learners want their own fonts, bold and
italic, letter spacing, small caps and ligature switches, variable-font weight, and a heading and
body in one text. All of it must stay deterministic and must not change an old snapshot.

## Fonts and styles (T11, T12)

- `FontResource` is one font file: a HarfBuzz font, a fontTools glyph set and an outline cache.
  `_registry` holds them by key. The key is the file name, or `name~2` when two different files
  share a name.
- `load_font` resolves the path next to the sketch file, then the current folder
  (`_resolve_path`, shared with `load_image` and `load_svg`). It returns a small `Font` token
  holding only the key.
- `GraphicsState.font` is the key or `None`. `effective_font(state)` picks the loaded font, or
  one of four bundled files from `STYLE_FILES` (D-022 A: real bold and oblique files, not
  synthesised). With a loaded font `text_style` is ignored but remembered.
- The IR records the key only when not default, so portable snapshots hold a file name, never a
  path.

## Tracking, features, variations (T13, D-042)

All three are fields of `GraphicsState` (`text_tracking`, `text_features`, `font_variations`).
Features and variations are sorted tuples of pairs, so equal settings compare equal and hash.

```
Sketch.text_features(liga=False)  ─►  ("liga", False) in state
                                            │
text_settings(state) ─► tracking, features, variations ─► FontResource.shape(text, size, ...)
                                            │
        location = font.location(variations)   (own axes only; others ignored)
              ├─► _at(location) = (HarfBuzz font with set_variations, fontTools glyph set at location)
              ├─► hb.shape(...)  advances at that location
              └─► TextRun(location=...) ─► outline(gid, location)   outlines at the SAME location
```

The invariant: **shaping and outlines use one variation location.** `_at` builds both from the
same dict and caches the pair. `TextRun.location` carries it to `outline_ops`, and the outline
cache key is `(location, gid)`. If they disagreed, spacing would not fit the glyph shapes.
A test font with a `wght` axis that changes both box width and advance is generated by
`tests/fontmaker.py` using fontTools, so nothing is downloaded.

- Tracking is added after every glyph, the last too (`TextRun.advance` adds
  `tracking * len(glyphs)`; `outline_ops` adds it per pen step). A ligature is one glyph.
- Features are merged on top of `{"kern": True, "liga": True}` in `shape`. Calls add to each
  other. `_tag` pads a short tag with spaces.
- An axis the font lacks is ignored (`location`), as DrawBot does. The bundled DejaVu files are
  static, so `font_variations` does nothing for them.
- `text_ascent` and `text_descent` come from `hhea` at the default instance. Variation
  changes to the metrics (MVAR) are not read.

## The shaped-run cache

`CairoRenderer._text_runs` is an LRU of `TextRun`, capped at `TEXT_RUN_CACHE_SIZE` (256) so
`f.text(f.frame_count, ...)` cannot grow it. The key is `(text, size)` for the plain default.
It gains the font key or style name away from the default, and `(tracking, features,
variations)` only when one is set. So the old key, and the tests that pin it, did not change.
`attach()` clears it. Outlines are cached separately on `FontResource` and live for the process.
`outline_ops` still transforms every glyph each time it is called.

## Layout: `text_box`, alignment and leading (T7, T9, T10)

One layout serves `text`, `text_box` and `text_path` (F13): `Sketch._line_layout` yields
`(line, left, top)`. The Sketch resolves alignment first, so an `ir.Text` op's (x, y) is always
its top-left. Each line is its own op.

- `typography.wrap_lines` breaks at spaces and breaks a long word between letters. It returns the
  lines and `rests[i]`, the text from line i on, so the overflow is `rests[fitting]`.
- A line fits while `fitting * leading + ascent + descent <= height`. Automatic leading is
  `1.25 * text_size` (p5).
- `text_box` returns the text that did not fit, or `""`.

## FormattedString (T14, D-044)

```
fs = f.FormattedString().append("Big", size=40).append(" small", tracking=2)
f.text(fs, x, y)
  └─► _fs_resolve : run.apply(style) for each run   (a given setting wins, others follow the state)
      _fs_pieces  : measure each (text, run) piece
      _fs_metrics : per line, tallest ascent and descent; step = the line's own leading
      _fs_layout  : shared baseline per line; pieces placed left to right
      └─► one ir.Text per piece, each with its own resolved GraphicsState
```

- `Run` is a frozen record where `None` means "not given". `FormattedString` holds a tuple of runs
  and is immutable apart from `append`, which returns `self`.
- No new IR op. Each piece is a plain `Text` op, so renderers, exports, `text_path` and snapshots
  need no change. A plain `str` takes the old code path and makes exactly the same ops.
- `FormattedString.wrap(fits)` is the shared line breaker. `_fs_text_box` returns the overflow
  with `fs._from(start)`, which keeps each run's settings.
- A run's colour is read by `append`, in the colour mode of the active sketch.
- Kerning is not applied across run boundaries: each run is shaped alone. A run's features and
  variations replace the state's rather than merge.

## Alternatives rejected

- **A markup string** for mixed text (D-044): DrawBot's `FormattedString` was chosen instead.
- **Names other than DrawBot's** for tracking and features (D-042): kept DrawBot's, with the
  `text_` prefix where funground's other text settings have it.
- **Synthesised bold and italic (D-022 B, C)**: bundled real files (about 2 MB).

## Invariants and edge cases

- Unknown style gives `ValueError` listing the four. Missing font file: `FileNotFoundError` naming
  both places looked. Not a font: `ValueError`.
- Default settings are not recorded in the IR (`OMIT_WHEN_DEFAULT`).
- Two files named alike in one run get `~2`. Their cache keys differ.

## Limits and open questions

- A loaded font whose key equals a style name (a file literally named `bold`) would share a cache
  key with `text_style("bold")`. Theoretical; not tested.
- **Real text in PDF (T15, D-043, S-094)** changes how the PDF exporter draws these `Text` ops. It
  is not built in this tree yet, so it is not described here. It needs its own note when it lands.
- `Run.size` is truncated to an integer, like `text_size`.
