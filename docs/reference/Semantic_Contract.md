# Playground Public Semantic Contract

**Status:** Phase 0 deliverable — every "v0.5 verified" cell was checked against `src_v0.5/playground/_core.py`
and by probe on the Windows teaching machine (24 Sept 2026). All rows are pinned; the ones that
change learner-visible output (C6, S2, S4) took effect together when Cairo became the renderer in
Sprint 3, with one deliberate golden regeneration (commit noted in `sprints/sprint-03/review.md`). Decisions are indexed in `Decision_Log.md`
(`D-nnn`). Tests: `tests/test_semantics.py` pins the *v0.5 verified* column today and moves to the
*v0.6 rule* column in the same change that applies it.

The rule, from the architecture document: *Playground owns concepts and public semantics; libraries
provide capabilities.* This table is what "owns" means.

## Text

| # | Semantic | v0.5 verified behaviour | v0.6 rule | Status |
|---|---|---|---|---|
| T1 | Anchor | (x, y) is the **top-left** of the rendered glyph box | Same | Pinned |
| T2 | Font | pygame's bundled `freesansbold.ttf` via `Font(None, size)`; no way to choose a font | **DejaVu Sans** (Bitstream Vera licence, 757 KB) bundled with Playground. Mechanism: glyph outlines read by fontTools, positioned by uharfbuzz, emitted as path ops in the IR — deterministic on every platform and renderer. Known limitation, accepted: exported PDFs carry outlines, not searchable text, until fonts are embedded (S-032) | Pinned (D-006, D-009) — in effect since Sprint 3 |
| T3 | Size | pygame `Font(None, size)` semantics (size 20 → ~13 px glyph height) | **`text_size(n)` is an n-pixel em** in logical pixels — the CSS/p5/DrawBot convention. Text therefore renders ~1.4× larger than v0.5 at the same number; a deliberate, one-time change | Pinned (D-012) — in effect since Sprint 3 |
| T4 | Colour | explicit `color=` → current fill → current stroke → white | Same | Pinned |
| T5 | Message | Any object; `str()` is applied | Same | Pinned |
| T6 | Measurement | — (v0.5 had no way to measure text) | `text_width(message)` returns the **advance width** of `str(message)` in logical pixels at the current `text_size`: the shaped run's kerned advance (T2), exactly the distance `text()` moves its pen, so `text(msg, (width - text_width(msg)) / 2, y)` centres it. Independent of the transform stack (`scale(2)` doubles the drawing, not the number); `""` → `0.0` | Pinned (S-037, Sprint 4) |
| T7 | Alignment (S-049) | — (always top-left, T1) | `text_align(horizontal, vertical=None)`: horizontal `"left"` (default), `"center"`, `"right"`; vertical `"top"` (default), `"center"`, `"baseline"`, `"bottom"`. Omitting `vertical` keeps the current one (p5). The point (x, y) given to `text()` becomes that point of the run: centre = x − width/2, right = x − width (width as T6); baseline = y − ascent, bottom = y − (ascent + descent), centre = y − (ascent + descent)/2 (ascent and descent as T8). With the defaults, T1 holds unchanged. Part of the saved state (`push`/`pop`, `saved_state`). The Sketch resolves alignment before emitting the op, so an IR `Text` op's (x, y) is always its top-left; the style fields are recorded only when not default. Unknown names → `ValueError` listing the valid ones. p5's default vertical alignment is baseline; ours stays top (User Guide chapter 14) | Pinned (Sprint 6) |
| T8 | Metrics (S-049) | — | `text_ascent()` and `text_descent()` return how far the font reaches above and below the baseline at the current `text_size`, in logical pixels, both positive: the default font's `hhea` ascent and −descent scaled to the em (DejaVu Sans: about 0.93 and 0.24 em). Independent of the transform stack, like T6 | Pinned (Sprint 6) |
| T9 | Several lines (S-053) | — (a newline had no defined meaning) | A `"\n"` in `text()` starts a new line. Lines are `text_leading` apart, baseline to baseline: `text_leading(n)` in logical pixels (≥ 0), or `None` for automatic, **1.25 × `text_size`** (p5's default), part of the saved state. `text_align` applies to the block: horizontally each line on its own; vertically the block's height is ascent + descent + leading × (lines − 1). Blank lines keep their place and emit nothing. `text_width` of several lines is the widest line's. Each line is its own IR `Text` op | Pinned (Sprint 6) |
| T10 | Text box (S-053) | — | `text_box(message, x, y, width, height=None, color=None)` wraps at spaces so no line is wider than `width` (T6 widths); a word wider than the box is broken between letters; `"\n"` always breaks. With a `height`, only whole lines fit: a line fits while its top + ascent + descent ≤ `height`. **Returns the text that did not fit**, starting at the first line not shown (`""` when all fit), so it can flow into the next box (DrawBot's `textBox`). Alignment is inside the box: left/centre/right of `width`; top and baseline at the box top, centre and bottom within `height` (without a height, at the top). `width` ≤ 0 or a negative `height` → `ValueError`. A separate function rather than more `text()` parameters, because `text()`'s v0.5 signature is frozen | Pinned (Sprint 6) |
| T11 | Fonts (S-054) | — (one font, T2) | `load_font(path)` reads a TrueType/OpenType file (`.ttf`, `.otf`) and returns a font. A relative path is found **next to the sketch file** first, then in the current folder. A missing file → `FileNotFoundError` naming both places looked; a file that is not a font → `ValueError`. `text_font(font, size=None)` makes later text use `font` (a font from `load_font`, or a path, which is loaded) and, if given, sets `text_size`; `text_font(None)` returns to the built-in family. Part of the saved state. `text_width`, `text_ascent`, `text_descent`, `text_box` and alignment measure with the current font. Text stays glyph outlines (T2), so a loaded font renders identically everywhere and stays vector in PDF/SVG. In the IR a font is recorded by its **file name** (e.g. `"DejaVuSansMono.ttf"`), not its path, so snapshots are portable; two different files with the same name in one run get `"name~2"`. Default (built-in, normal) is recorded as nothing, so existing snapshots are unchanged | Pinned (Sprint 6) |
| T12 | Text styles (S-054, D-022 = A) | — | `text_style(style)`: `"normal"` (default), `"bold"`, `"italic"`, `"bold_italic"` (p5's four). With the built-in family each is a **real bundled file**: DejaVu Sans, Sans Bold, Sans Oblique, Sans Bold Oblique (DejaVu 2.37, Bitstream Vera licence, shipped with funground). With a loaded font `text_style` has no effect (load the bold or italic file itself, as in p5); it is remembered and applies again after `text_font(None)`. Part of the saved state. Unknown style → `ValueError` listing the four | Pinned (Sprint 6) |

|---|---|---|---|---|

| R2 | Callbacks | `setup()` optional, once; `draw()` required, repeated; found by name in the calling script's globals; non-callables raise `TypeError`, missing `draw` raises `RuntimeError` | Same | Pinned |
| R3 | `run()` | Keyword-only `fps=None`; **Phase 0 adds** keyword-only `max_frames=None` | Same | Pinned |
| R4 | Frame counting | `draw()` sees `frame_count == 0` on its first call; `frame_count` = completed frames; incremented after `draw()` | Same | Pinned |
| R5 | `delta_time` | Seconds taken by the previous frame; `0.0` during the first `draw()` | Same | Pinned |
| R6 | Stopping | Window close, Escape, or `p.stop()`; the loop ends after the current `draw()` | Same. Escape-quits stays (teaching convenience) | Pinned |
| R7 | Re-running | **v0.5 bug:** a second `p.run()` in one process crashed unless `setup()` called `size()` (dead display surface kept). Fixed in Phase 0 | Works | Pinned |
| R8 | Headless | Works with `SDL_VIDEODRIVER=dummy`; used by the test suite | A first-class headless/export mode later | Pinned |
| R9 | Errors | Drawing before `size()` → `RuntimeError` naming `p.size`; non-positive size/fps → `ValueError` | Same; unsupported-capability errors name the extra to install | Pinned |
| R10 | Loop control and clock (S-048) | — | `no_loop()` stops calling `draw()` each frame; the window stays open and events are still handled. `draw()` **always runs on the first frame**, even after `no_loop()` in `setup()` (p5). `redraw()` runs `draw()` once more; `loop()` resumes; `is_looping()`. `frame_count` counts `draw()` calls only. `run(max_frames=n)` counts loop iterations, so non-looping sketches end too. `millis()` = whole milliseconds since `run()` started; `frame_rate()` = measured fps (smoothed; 0.0 before the second frame). `exit()` = `stop()`. `second() minute() hour() day() month() year()` from the local clock | Pinned (Sprint 5) |
| R11 | Frame sequences (S-056) | — | `save_frames(pattern, count)` saves the frame it is called in and the following drawn frames, `count` in all, exactly as `save()` would (PNG = pixels on screen, PDF/SVG = that frame's vector replay). The pattern has exactly one run of `#`, replaced by the sequence number 1, 2, … zero-padded to the run's length (`####` → `0001`); a longer number is not cut. The file's folder is created if missing. Only drawn frames count, so a paused sketch saves on `redraw()`. Calling it again starts a new sequence; a run that ends first just stops. No `#` or more than one run, an unsupported extension, or `count` < 1 → `ValueError` at the call | Pinned (Sprint 6) |
| R12 | Window control (S-057) | — | `resize_canvas(w, h)` is `size(w, h)` keeping the title and fps: allowed while running; `width`/`height` change at once; the canvas starts blank at the new size; HiDPI is recomputed, so drawing stays sharp. On the SDL high-DPI route the same window is resized, never a second one opened. `full_screen()` (instead of or after `size`) fills the main display: `width`/`height` become its size in logical pixels; Escape still ends the sketch; `size`/`resize_canvas` return to a window. Headless, the "display" is a fixed **1920 × 1080** so runs repeat. `cursor(kind="arrow")` with `"arrow"`, `"cross"`, `"hand"`, `"move"`, `"text"`, `"wait"` (p5's six); `no_cursor()` hides it over the canvas. The choice may be made before the window exists and is applied whenever one opens. Unknown kind → `ValueError` | Pinned (Sprint 6) |
| R13 | Two styles of program (S-076, D-029 = D) | Only animated sketches | A file is **either** an animated sketch (`setup()` optional, `draw()` required, started by `f.run()`; unchanged, R2) **or** a script: drawing at the top level with no `setup()`/`draw()` and no `f.run()` (DrawBot style). `f.run()` with `setup()` but no `draw()` → `RuntimeError` that offers both: add `draw()` to animate, or remove `setup()` and `f.run()` and write it as a script. `f.run()` after top-level drawing → `RuntimeError` saying the file mixes the two styles. When a program run from a terminal ends with a callable `draw` in `__main__` and `f.run()` never called, funground prints one line to stderr at exit: "Your sketch has a draw() function but never started. Add f.run() as the last line." (Not shown in interactive sessions, nor after the program ended with an error; IDLE and Thonny cannot trigger it.) A top-level `f.size()` alone is not drawing: a draw-only sketch may call it before `f.run()` and keeps that size | Pinned (Sprint 7) |
| R14 | Scripts (S-076) | Top-level `size()` opened a window; `save()` then wrote nothing (silent) | In a script, `f.size(w, h)` makes a canvas **without opening a window**; drawing before it → `RuntimeError` (R9); calling it again starts a new blank canvas. Everything drawn is kept as the canvas's drawing. `f.save(path)` writes **immediately**: PNG = the canvas's pixels at the backing scale (1 headless, `FUNGROUND_BACKING_SCALE` if set), PDF/SVG = the drawing as vectors. Nothing resets: state, transform and `push` depth carry on, as in a picture (P2). Input values stay 0, `frame_count` is 0, `millis()` counts from `size()`. Animation-only functions (`no_loop`, `loop`, `redraw`, `save_frames`, `exit`) raise `RuntimeError` naming the animated style. `create_graphics`, `image`, fonts and everything else work | Pinned (Sprint 7) |
| R15 | `show()` (S-076) | — | `f.show()` opens a window at the canvas's logical size, draws the canvas's drawing at the window's backing scale (sharp on HiDPI), and **waits until the window is closed or Escape is pressed**; then the script continues and may draw, save and show again. Headless (`FUNGROUND_HEADLESS=1`) it returns at once. In an animated sketch it raises `RuntimeError` (the window is already there). Before `size()` → `RuntimeError` (R9) | Pinned (Sprint 7) |

## Reserved for Phase 2 (not in v0.5)

| # | Semantic | Proposed rule | Status |
|---|---|---|---|
| F1 | Angle unit for `rotate()` | **Degrees**: `p.rotate(90)` is a quarter turn. `p.radians(deg)` and `p.degrees(rad)` helpers for trigonometry. No angle-mode switch | Pinned (D-002) |
| F2 | Transform state | `translate(dx, dy)` / `rotate(degrees)` / `scale(s)` / `scale(sx, sy)` are **cumulative**: each multiplies the current transform (local geometry first, so `translate` then `rotate` turns about the new origin, and the reverse order rotates the translation too) and applies to **all later geometry and text** (images when they arrive) until restored. `push()` saves the transform **and** the style (fill, stroke, stroke width, text size) on one stack; `pop()` restores both — restore restores everything. `with p.saved_state():` is push on entry, pop on exit, exception-safe. **Transforms reset at the start of every `draw()`** (as in p5/Processing): a `translate`/`rotate`/`scale` never carries into the next frame, pushed or not. **Style does not reset**: a `fill()`/`stroke()`/`text_size()` set inside `draw()` *without* a push stays current for the next frame, exactly as in p5/Processing (S3); only state saved by an open `push()` is unwound. Safety: pushes left open at the end of `draw()` are popped by Playground with a `PlaygroundWarning` naming the count; a `pop()` without a `push()` warns and is ignored; `scale(0)` is a `ValueError` at the call site. `background()` ignores the transform (S9) | Pinned (S-027, Sprint 4) |
| F3 | Shapes, paths and clipping | `begin_shape()` / `vertex(x, y)` / `bezier_vertex(cx1, cy1, cx2, cy2, x, y)` (was `curve_vertex` until D-018) / `end_shape(close=False)` build a shape from its corners; `p.path()` returns a reusable builder (`move_to`, `line_to`, `curve_to`, `quad_to`, `close`, each returning the builder) drawn with `draw_path(path)`. Both use the **current fill and stroke** (S3, S8) at the moment they are drawn, fill first then stroke (S5), stroke centred (S4). **Fill rule is non-zero (winding)**: a self-crossing outline such as a pentagram is filled right through its centre. **Open shapes are stroked, never filled**: a shape or path is filled only when it is closed (`end_shape(close=True)`, or every sub-path of a `p.path()` ends with `close()`); a fill that is set but unused is not an error. `quad_to` is stored as its exact cubic equivalent, so every backend needs one curve kind. `clip(path)` limits all later drawing to the inside of the path (implicitly closed, same fill rule) and follows the current transform; it is **lifted by the `pop()` of the enclosing `push()`** / end of the `with p.saved_state():` block, and, like transforms, never survives into the next `draw()` (F2). `background()` ignores the clip (S9). A shape left open at the end of `draw()` is dropped with a `PlaygroundWarning`; `vertex()`/`end_shape()` outside `begin_shape()`, `begin_shape()` twice, or `curve_vertex()` before the first `vertex()` are `RuntimeError`s at the call site | Pinned (S-028, Sprint 4) |
| F4 | `rect`/`ellipse` mode switches | Not offered; anchoring is fixed as above (one rule, no `rectMode`). *(Was F3 until Sprint 4 gave F3 to paths, as the sprint plan numbered it.)* | **Superseded by F10** (D-030 = B, 1 Oct 2026): the defaults stay as above; modes can now change them |
| F10 | Drawing modes (S-081, D-030 = B; p5's modes) | Fixed anchors (F4) | Three saved-state settings, **defaults unchanged**: `rect_mode(mode)` for `rect` and `square`: `"corner"` (default; x, y = top-left, then width, height), `"corners"` (x1, y1, x2, y2 = two opposite corners, in any order), `"center"` (x, y = centre, then width, height), `"radius"` (x, y = centre, then half-width, half-height). `ellipse_mode(mode)` for `ellipse`, `circle` and `arc`: `"center"` (default; x, y = centre, then diameters), `"radius"` (x, y = centre, then radii), `"corner"` (x, y = top-left of the bounding box, then width, height), `"corners"` (two opposite corners of the bounding box). `image_mode(mode)` for `image`: `"corner"` (default; x, y = top-left, then optional width, height), `"corners"` (x, y = one corner, the next two numbers the opposite corner; both required), `"center"` (x, y = centre; without a size, the picture's own size). `square` and `circle` take one size, so under `"corners"` they behave as `"corner"`. In `"corners"` the corners may be given in any order; the shape spans them. The mode is part of the saved state (`push`/`pop`, `saved_state`) and of a picture's state (P2), and persists across frames like `fill` (F2). Unknown mode → `ValueError` listing the valid ones | Pinned (Sprint 7) |
| S11 | Stroke styles (S-042) | `stroke_cap("round"\|"square"\|"butt")` — `square` extends half the stroke width past the end, `butt` stops flat (DrawBot/SVG names; Processing's `SQUARE` is our `"butt"`, its `PROJECT` our `"square"`). `stroke_join("round"\|"miter"\|"bevel")`; `miter_limit(n)`, n ≥ 1, default 10. `stroke_dash(pattern, offset=0)` with one length or a list, `no_dash()`.
