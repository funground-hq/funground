## Findings

1. **"Internal capability first, public API later" worked exactly as intended.** Every verb in
   this sprint was a thin layer over IR ops that Sprint 2/3 already rendered and tested. The
   whole public surface for transforms, the stack, paths and clipping is ~80 lines of `api.py` and
   ~150 lines of `sketch.py`; no renderer semantics changed.
2. **The window context persists across frames — the renderer had to defend itself.** A
   learner's top-level `p.translate()` in `draw()` leaked into the next frame through Cairo's live
   context until `draw()` was wrapped in `save()/restore()`. This is the same class of bug the
   Sprint 3 guide warned about (Save/Restore depth), now closed at both ends: `Sketch._end_draw()`
   unwinds the learner's stack, the renderer resets its own.
3. **Frame-end safety is a warning, never a crash.** An open `push()` at frame end, a stray
   `pop()`, and an unfinished `begin_shape()` all warn with `PlaygroundWarning` (new
   `UserWarning` subclass in `capabilities.py`) and continue. `scale(0)` is the one hard error,
   raised at the call site. This is the pattern to keep for every future learner-facing verb.
4. **Verifiers caught what the implementer reports did not:**
   - Contract F2 says "a transform or style set inside `draw()` never carries into the next frame".
     A probe shows an *unpushed* style set inside `draw()` **does** persist (white, blue, blue —
     as in p5 and per S3). Only the stack and the transform reset. The sentence needs correcting
     before F2 is treated as pinned. *(Open — not fixed in this sprint's commits.)*
   - The contract's "Test coverage" paragraph still claims every Pinned row is tested in
     `test_semantics.py` or `test_api_contract.py`; F2, F3 and T6 are tested in
     `test_transforms.py`, `test_paths.py` and `test_text.py`. *(Open — one-paragraph doc fix.)*
   - S-037's acceptance line says 10 000 frames; the committed test runs 1 000 frames directly
     against `CairoRenderer.render`, not through the run loop. The verifier confirmed the 10 000
     -frame behaviour with a throwaway script, so the code is right and the test under-states
     the criterion. *(Open — consider lifting the test to the acceptance line.)*
   - `typography.text_width` shapes on every call and does not share the renderer's LRU, so
     `p.text_width(msg)` in `draw()` shapes each frame. Cheap; noted as a possible follow-up.
5. **macOS/Linux HiDPI is a code path, not a verified feature.** pygame-ce's `set_mode` never
   sets `SDL_WINDOW_ALLOW_HIGHDPI`; `pygame.Window(allow_high_dpi=True)` does, and since SDL 2.26
   the surface is drawable-sized while `Window.size` is in points. The ratio is the scale. Six
   tests fake `pygame.Window` at 2× and 1× under patched `sys.platform`; nothing has run on a
   Retina Mac or Wayland desktop. The designed fallback (ratio 1.0 → runs, not crisp) is the
   worst case.
6. **The Quick Reference is now produced by the code it documents.** `tests/test_reference.py`
   makes S-030's acceptance line executable: every `__all__` name appears as `p.<name>`, every
   embedded sketch is verbatim from `examples/reference/` and renders headless, every image
   exists at 640×400. A PDF render was not done (no toolchain in the repo); the v0.5 PDF remains
   the colour appendix.
7. **The browser route is real (Spike 08).** The core needs no source change to run in Pyodide;
   the per-frame Python cost is under 1 ms; the blocker is the blocking `while self.running`
   loop (S-060, loop inversion) and the shaper (uharfbuzz has no wasm wheel — S-063). The IR →
   JSON → JavaScript renderer path is cheap enough to be the first browser renderer.
8. **Public vocabulary grew by 16 names in one sprint** (v0.5 had 19 functions; `__all__` is now
   45 entries including live values). All additive, all in `ADDED_FUNCTIONS`, but this is the
   largest single expansion the Quick Reference has had to absorb; worth a pass for names a
   beginner will confuse (`path` vs `draw_path`, `state` vs `push`).

## Retrospective

- *Went well:* the additive checkpoint held without effort — five stories touched the sketch,
  renderer and platform and not one pre-existing golden or snapshot byte moved. Naming every public
  verb in the sprint plan meant only one decision (D-013) had to be raised. The reference test
  turns "documents every function" from a claim into a failing test.
- *What the verifiers caught:* three documentation drifts (F2 wording, the contract's test-coverage
  paragraph, an S-037 test that under-states its acceptance line) and one performance nit
  (`text_width` outside the cache). None is a behaviour bug; all four are cheap. The lesson is that
  a contract row written while the code is fresh can state a rule slightly stronger than the code
  keeps — the verifier's probe, not the implementer's tests, found it.
- *Went badly:* S-039 could not start — there is still no remote, so the 12-cell matrix has never
  run and every count in this document is Windows-only. S-038 shipped code nobody has run on the
  hardware it targets; that is stated plainly everywhere but it is still unverified code in the
  platform layer.
- *Carry-over:* S-039 (blocked on a remote — needs the maintainer to create one). Open doc fixes
  from Findings 4 (F2 wording, test-coverage paragraph, 10 000-frame test). S-038 hardware
  verification by a maintainer with a Retina Mac or Wayland desktop. Possible follow-ups:
  `text_width` cache sharing; S-060/S-062/S-063 from Spike 08 for the browser route.
